# Padший Сёгун / Samurai Shogun — GeckoLib 4 boss (Forge 1.20.1)

3-блочный (48 юнитов) кастомный босс: геометрия, анимации, текстура и Java-классы.

## Структура

```
assets/modid/geo/samurai_shogun.geo.json
assets/modid/animations/samurai_shogun.animation.json
assets/modid/textures/entity/samurai_shogun.png            (256x256)
assets/modid/textures/entity/samurai_shogun_glowmask.png   (emissive)

java/com/example/samurai/SamuraiMod.java
java/com/example/samurai/registry/ModEntities.java
java/com/example/samurai/entity/SamuraiBossEntity.java
java/com/example/samurai/client/SamuraiBossModel.java
java/com/example/samurai/client/SamuraiBossRenderer.java

java/com/example/samurai/client/vfx/SwordTrail.java
java/com/example/samurai/client/vfx/CameraShake.java
```

Положите `assets/` в `src/main/resources/`, `java/` — в `src/main/java/`.

## Перед запуском

1. Замените `modid` на свой mod id — **в двух местах**: имя папки `assets/<modid>/`
   и константа `SamuraiMod.MOD_ID`. Путей в Java менять не нужно, они собираются
   из этой константы.
2. Замените пакет `com.example.samurai` на свой, если нужно.
3. `build.gradle`:

```gradle
repositories {
    maven { url 'https://dl.cloudsmith.io/public/geckolib3/geckolib/maven/' }
}
dependencies {
    implementation fg.deobf("software.bernie.geckolib:geckolib-forge-1.20.1:4.4.9")
}
```

4. `META-INF/mods.toml` — добавьте зависимость:

```toml
[[dependencies.modid]]
    modId = "geckolib"
    mandatory = true
    versionRange = "[4.4,)"
    ordering = "NONE"
    side = "BOTH"
```

5. Лангфайл `assets/modid/lang/en_us.json`:

```json
{ "entity.modid.samurai_shogun": "Corrupted Shogun" }
```

## Меч

Клинок разбит на три кости (`blade_1` → `blade_2` → `blade_3`), каждая повёрнута
на несколько градусов по Z. Сумма даёт **сори** — изгиб настоящей катаны; одним
кубом он невозможен. Лезвие по оси −X, обух по +X, поэтому клинок должен
выгибаться в сторону +X: `x' = -dy·sin(rz)`, значит `rz` **отрицательный**.

Фурнитура на кости `katana`: касира (навершие), цука с оплёткой ито, фути,
цуба с прорезями и хабаки. Общая длина ~52 юнита (3.25 блока) — нодати.

Изгиб лежит в плоскости Z, а анимации крутят меч по X, так что кривизна
смещает остриё вбок, а не вниз: вертикальный вылет меняется всего на ~2%,
и углы в клипах переподбирать не нужно.

## Текстура: per-face UV, 256×256

Модель использует **per-face UV**, а не box UV. Это сознательный выбор: при box UV
развёртка жёстко привязана к размеру куба в игровых юнитах — 1 тексель на юнит,
и поднять детализацию просто увеличением картинки невозможно. При per-face UV
каждая грань несёт свои `uv` и `uv_size`, поэтому здесь стоит **2 текселя на юнит**
(вчетверо больше пикселей). Нагрудная пластина 14×16 юнитов занимает 28×32 текселя.

GeckoLib 4 это читает — проверено по исходнику ветки 1.20.1:
`loading/json/raw/UVUnion.java` принимает и массив (box UV), и объект граней,
а `UVFaces`/`FaceUV` разбирают `north/south/east/west/up/down` с `uv_size`.

Последствия, о которых стоит знать:

- В Blockbench проект откроется в режиме per-face UV. Вкладка UV редактируется
  **по одной грани**, а не единой развёрткой куба. Не переключайте проект
  обратно в box UV — развёртка схлопнется в 1 тексель на юнит, и половина
  детализации пропадёт.
- Если добавляете новые кубы вручную, им тоже нужны per-face UV; Blockbench
  по умолчанию может создать их в box-режиме, и тогда они возьмут неверный
  участок атласа.
- Атлас занят на 55%, свободные строки снизу — место под новые детали.

Эмиссия (`_glowmask.png`) — 1.3% атласа: только глаза, кромка клинка и трещины
скверны. Броня и золото не светятся намеренно, иначе ночью силуэт превращается
в сплошное пятно.

## Иерархия костей

```
root  (locators: ground_impact, aura)
└── waist
    ├── kusazuri                 — набедренные пластины (отлетают в death)
    ├── torso
    │   ├── head
    │   │   ├── menpo            — маска, y36–40 (отлетает в death)
    │   │   └── kabuto           — шлем + сикоро
    │   │       ├── horn_right → horn_right_tip   — кувагата, 2 сегмента
    │   │       └── horn_left  → horn_left_tip
    │   ├── right_shoulder  (содэ)
    │   │   └── right_arm
    │   │       └── katana       — рукоять, фути, цуба, хабаки
    │   │           └── blade_1 → blade_2 → blade_3
    │   │                         (сегменты клинка, дают изгиб сори;
    │   │                          locators blade_mid и blade_tip)
    │   └── left_shoulder   (содэ)
    │       └── left_arm
    ├── right_leg → right_boot → right_foot
    └── left_leg  → left_boot  → left_foot
```

Кости `*_boot` — это наголенник (сунэатэ), `*_foot` — ступня, выезжающая вперёд.
Клипы анимируют `*_boot`; ступни наследуют поворот, поэтому клип, который их
не упоминает, ничего не ломает. В `walk` для ступней добавлен перекат: носок
вверх при постановке и толчок носком при отрыве.

Высота корпуса: ровно `y = 0 … 48` (3 блока). Ширина с содэ — 24 юнита (1.5 блока),
что совпадает с хитбоксом `.sized(1.6F, 3.0F)`.

Клинок в rest-позе торчит до `y = 64`, потому что кость `katana` в T-позе смотрит
вверх. В анимациях она повёрнута на ~-104°, так что силуэт остаётся в 3 блока.
`visible_bounds` уже расширены, чтобы босс не исчезал при повороте камеры.

## Анимации

| Клип | Длина | Loop | Что делает |
|---|---|---|---|
| `idle` | 4.0 s | да | широкая стойка, дыхание, катана покачивается у пояса |
| `walk` | 1.6 s | да | тяжёлый шаг, корпус подкручивается, меч стабилизирован |
| `attack_slash` | 1.0 s | нет | рывок вперёд + горизонтальный иайдо-рез, возврат в стойку |
| `attack_heavy` | 1.8 s | нет | замах над головой, шаг, удар в землю (ударная волна) |
| `defend_stance` | 2.0 s | да | блок плоскостью клинка, присед |
| `death` | 3.2 s | hold | меч выпадает из рук, колено, поклон, доспех разлетается |

Импакт-кадры, с которыми синхронизирован урон в Java:
`attack_slash` — 0.38 s (8 тиков), `attack_heavy` — 1.00 s (20 тиков).

### Конвенция поворотов (важно при правке)

В Blockbench/GeckoLib знак оси X не такой, как в «обычной» правой системе:

- **Конечность (рука, нога)** висит вниз от пивота → **отрицательный X = вперёд**.
- **Корпус (`waist`, `torso`, `head`)** растёт вверх от пивота → **положительный X = наклон вперёд**.
- **`katana`** в T-позе смотрит **вверх** (+Y), поэтому её X читается как «градусов от вертикали»:
  `0` — клинок строго вверх, `~90` — горизонтально вперёд, `~180` — строго вниз.

Повороты родителя и ребёнка складываются, поэтому значения `katana` в каждом кадре
подобраны **против угла `right_arm` в том же кадре**. Если меняете позу руки —
пересчитайте и меч, иначе клинок уедет в землю. Пример из `attack_heavy` @0.55:
`right_arm = -172` (рука над головой) + `katana = 172` → итог `0` = клинок строго вверх.

## Эффекты (след от меча, пыль, тряска)

Три клиентских класса в `client/vfx/`:

| Класс | Что делает |
|---|---|
| `SamuraiVfx` | разбирает particle/sound-кейфреймы: пыль, искры, звуки |
| `SwordTrail` | ленточный след за клинком |
| `CameraShake` | тряска камеры |

**Пакеты не нужны.** GeckoLib обсчитывает анимации на клиенте, поэтому
particle-хук срабатывает у каждого игрока, который видит босса. Оттуда же
запускается и тряска. Но `registerControllers` вызывается на обеих сторонах,
поэтому `SamuraiVfx` дёргается строго через `DistExecutor` — прямая ссылка
уронила бы выделенный сервер при загрузке клиентских классов.

### След от меча

`SwordTrail` каждый кадр берёт мировые позиции костей `blade_base` и `blade_tip`
и сшивает соседние сэмплы в четырёхугольники — лента получается шириной с
клинок и повторяет его изгиб, а не тянется ниткой за остриём.

Сэмпл берётся только если остриё сдвинулось больше чем на `MIN_TRAVEL`
(0.22 блока), поэтому в idle и walk следа нет — спрашивать, какая анимация
играет, не требуется. Позиции хранятся в мировых координатах и рисуются
относительно текущей позиции сущности, так что лента остаётся висеть в воздухе,
пока босс проскакивает сквозь неё в рывке `attack_slash`.

Рисуется через `RenderType.lightning()` — это POSITION_COLOR с аддитивным
смешиванием и без текстуры, то есть свой RenderType регистрировать не надо.

Настройки в начале `SwordTrail`: `LIFETIME_TICKS` (длина хвоста),
`MIN_TRAVEL` (порог срабатывания), `MAX_SEGMENTS`. Цвета — в методе `quad`:
у рукояти тусклый фиолетовый, у острия белое каление.

### Почему кости, а не локаторы

Изначально точки эффектов были Blockbench-локаторами. Так не работает:
GeckoLib парсит блок `locators`, но **не превращает их в кости**
(в `BakedModelFactory` нет ни одной ссылки на локаторы), а мировую позицию
умеет отдавать только `GeoBone.getWorldPosition()`. Поэтому в модели стоят
пустые кости-маркеры: `blade_base`, `blade_mid`, `blade_tip`, `ground_impact`,
`aura`. Строка `"locator"` в кейфрейме резолвится по **имени кости**.

Матрицы костей заполняются лениво: первый вызов `getWorldPosition()` только
включает отслеживание, а заполнится оно на следующем кадре. Поэтому и
`SwordTrail`, и `SamuraiVfx` пропускают нулевую позицию и откатываются на
центр сущности.

### Тряска камеры

В Minecraft её нет, поэтому `CameraShake` подкручивает углы в
`ViewportEvent.ComputeCameraAngles` и гасит амплитуду раз в тик.
`addAtDistance` масштабирует силу по расстоянию до игрока, чтобы удар на другом
конце арены не тряс экран так же, как удар под ногами. Удар в землю даёт 4.2°
с радиусом 22 блока, развал доспеха — 1.4° с радиусом 16.

### Пыль от удара в землю

`shockwave` берёт блок **под** боссом и сыплет его настоящей крошкой
(`BlockParticleOption`), поэтому на песке пыль песчаная, на камне — каменная.
Три расходящихся кольца, низкое облако дыма и фиолетовые искры.

### Звуки

Сейчас в `SamuraiVfx.onSoundKeyframe` подставлены ванильные звуки-заглушки
(наковальня, взрыв, свип). Замените на свои `SoundEvent` после регистрации —
маппинг имён уже на месте.

### Keyframe-эффекты

В JSON уже прописаны `sound_effects` и `particle_effects` с локаторами.
Обработчики — в `SamuraiBossEntity.registerControllers()`, тела оставлены пустыми:

```java
main.setParticleKeyframeHandler(event -> {
    String effect  = event.getKeyframeData().getEffect();   // "shockwave", ...
    String locator = event.getKeyframeData().getLocator();  // "ground_impact", ...
    // ваш спавн частиц
});
```

Имена эффектов: `samurai_step`, `samurai_slash`, `samurai_raise`, `samurai_slam`,
`katana_drop`, `armor_crash`, `armor_break`, `shockwave`, `corruption_slash`,
`corruption_burst`, `katana_plant`.

**`katana_plant` обязателен к обработке.** В `death` на 1.05 s кость `katana`
уходит в `scale: [0,0,0]` — меч покидает руку. Так сделано намеренно: клинок
длиной 50 юнитов, а кисть умирающего босса на высоте ~1 блока, поэтому
«воткнутый» меч, оставшийся привязанным к руке, ушёл бы под землю почти целиком.
На кадре 1.00 s спавните отдельный пропс (entity / armor stand с моделью меча)
в локаторе `ground_impact` — он и будет торчать из земли.

## Открыть в Blockbench

`File → Open Model` → `samurai_shogun.geo.json`. Формат определится как
**Bedrock Model**. Затем `Animation → Import Animations` → `samurai_shogun.animation.json`,
и в `Textures` подгрузите `samurai_shogun.png`.

Если правите модель в Blockbench — сохраняйте обратно в тот же `.geo.json`
(`File → Export → Bedrock Geometry`), имена костей менять нельзя, иначе
анимации и Java-хуки отвяжутся.

## Что стоит подкрутить под себя

- **Роги.** Знак поворота по Z решает, куда они расходятся: для правого рога
  (он на −X) наружу — это **положительный** rz, для левого — отрицательный.
  Углы 56° и 28° выбраны так, чтобы кончик встал ровно на y=48: более пологие
  роги выходят за 3 блока. Если хотите их выше — придётся либо поднимать
  хитбокс, либо опускать точку крепления ниже y=43.
- **Полоса глаз.** Маска `menpo` заканчивается на y=40, а козырёк `kabuto`
  начинается с y=42 — зазор в 2 юнита и есть прорезь, откуда светятся глаза.
  Если удлините маску или опустите шлем, лицо закроется наглухо и свечение
  пропадёт.
- **Позы рук.** `left_arm` в двуручном хвате выставлен через `position: [-13, -2, -5]` —
  это сдвиг кости, а не IK. Если поменяете ширину торса, подвиньте и это значение.
- **Колено в `death`.** Сгиб собран из двух костей: бедро `right_leg: +10°`
  (почти вертикально, колено уходит в землю) и голень `right_boot: +80°` (ложится
  назад). Опорная нога — `left_leg: -55°` / `left_boot: +55°`, чтобы ступня
  осталась плашмя. `root` опускается на 6 юнитов — это разница между высотой
  бедра стоя (20) и на колене (14). Если добавите отдельную кость голени,
  перенесите сгиб на неё и уберите компенсацию с `*_boot`.
- **Разлёт доспеха** сделан через `scale → [0,0,0]` на костях `kusazuri`, `menpo`,
  `kabuto`, `horn_*`, `*_shoulder`. Для настоящих падающих обломков спавните
  отдельные entity в particle-хуке на 2.10 s.
